# Пакет приёмки колл-центра: обезличенные сценарии для срезов КЦ

Этот каталог — то, чем проверяются платформенные срезы, нужные конфигурации
колл-центра, **без единого настоящего телефона, ФИО, адреса или секрета**. Всё
синтетическое: «Филиал 1», «Направление A», «Город Н», «улица Первая».

Пакет можно прикладывать к PR и заявкам целиком.

## Два варианта конфигурации

| Каталог | Что это | На чём проходит `onebase check` |
|---|---|---|
| `base/` | контрольный вариант: только то, что платформа умеет сегодня | любой свежий `main` |
| `full/` | целевой вариант КЦ: подчинённый справочник, глубокий источник подбора, булев литерал, пять ключей формы | только после слияния трёх срезов |

`full/` отличается от `base/` ровно тем, что даёт каждый срез, — по нему видно,
какой PR что разблокирует.

## Команды

```bash
# контрольный вариант на текущем main
onebase check --lint --project cc-acceptance/base
onebase migrate --project cc-acceptance/base --sqlite /tmp/cc-base.db
onebase procrun --proc ЗаполнитьДемоданные  --project cc-acceptance/base --sqlite /tmp/cc-base.db
onebase procrun --proc ПроверитьНеопределено --project cc-acceptance/base --sqlite /tmp/cc-base.db

# целевой вариант — той сборкой, которую проверяете
onebase check --lint --project cc-acceptance/full
```

## Сценарий → ожидаемое → фактическое → SHA

Прогон 2026-09-28. «Фактическое» — то, что напечатала названная сборка.

### 1. Грамматика подбора (PR #1769, план 183 B1)

| Сценарий | Ожидаемое | Фактическое | Сборка |
|---|---|---|---|
| `full`: `from: Объект.Направление.ГруппаНеисправностей` и `value: false` у булева реквизита | принимается | **ошибка** «from … не является явной ссылкой», «литерал value допустим только для is_folder» | `main` f2b60595 |
| то же | принимается | `OK: ошибок не найдено` | ветка #1769, f162299a |

### 2. Пять ключей элемента формы (PR #1774)

| Сценарий | Ожидаемое | Фактическое | Сборка |
|---|---|---|---|
| `full`: `scroll_x`, `primary`, `choice_folders`, `choice_dropdown`, `editable_admin_only` | ключи известны загрузчику и линту | **5 предупреждений** «неизвестный YAML-ключ … загрузчик его игнорирует» | `main` f2b60595 |
| то же | ключи известны | предупреждений по этим ключам нет | ветка #1774, aa13a1bc |

Важно: незнакомый ключ `yaml.v3` отбрасывает молча — конфигурация выглядит
рабочей, а поведение остаётся прежним. Именно поэтому ключ без поддержки хуже
ошибки.

### 3. Подчинённые справочники (PR #1696)

| Сценарий | Ожидаемое | Фактическое | Сборка |
|---|---|---|---|
| `full`: `owner: Направление` у справочника | ключ известен | **предупреждение** «неизвестный YAML-ключ "owner"» | `main` f2b60595 |
| то же | ключ известен | предупреждений по `owner` нет | ветка #1696, 89f2eb7d |
| Блокер 1 ревью (круг 2): round-trip конфигуратора сохраняет `std_owner` | сохраняется | сторож ветки `TestSaveFields_OwnerKeepsStandardID` — PASS | ветка #1696, 89f2eb7d |
| Блокер 2: колонка ТЧ со ссылкой на подчинённый справочник | отбор по владельцу есть | `refFilter` у колонки = `{"Владелец":{"from":"Направление","value":"…"}}`, предзагруженные варианты — только владельца | ветка #1696, 89f2eb7d |
| Блокер 3: `owner:` вместе с `choice_filter` | один запрос, один sequence gate | `obRefreshDependentSelects` делегирует в `obRefreshChoiceSelect(sel, true)` | ветка #1696, 89f2eb7d |

Ревью круга 2 проводилось против `84798ad9`; на текущем HEAD ветки все три
блокера воспроизвести не удалось.

**Побочная находка:** на ветке #1696 одна и та же ошибка `choice_filter`
печатается дважды (4 строки на 2 проблемы) — это ровно хвостовая заявка ревью
про двойной вызов `CheckFormChoiceFilter` в `configcheck/full.go`.

### 4. Серверный поиск подбора (PR #1495)

| Сценарий | Ожидаемое | Фактическое | Сборка |
|---|---|---|---|
| Обработчик события «Поиск» пытается записать справочник | запись не проходит (fail-closed, блокер P1) | **запись сохранилась**: в справочнике появилась строка «ЗАПИСЬ_ИЗ_ПОИСКА» | ветка #1495, fad6a55d |

Блокер P1 воспроизводится. Сценарий минимальный: форма с обработчиком
`Поиск`, создающим элемент справочника; событие вызывается обычным POST
`/ui/catalog/<сущность>/form-event` с `_event=Поиск`.

### 5. Совместимость `0` и `Неопределено` (заявка #1274, PR #1614)

Обработка `ПроверитьНеопределено` печатает четыре строки. Ожидаемое поведение
по заявке — первые три «Ложь», последняя «Истина».

| Строка | Ожидаемое | Фактическое | Сборка |
|---|---|---|---|
| `0 = Неопределено` | Ложь | **Истина** | `main` f2b60595 |
| `Соответствие["Повторы"] = Неопределено` (значение 0) | Ложь | **Истина** | `main` f2b60595 |
| пустая строка `= Неопределено` | Ложь | Ложь | `main` f2b60595 |
| отсутствующий ключ `= Неопределено` | Истина | Истина | `main` f2b60595 |

Заявка #1274 закрыта как выполненная 2026-09-28, но PR #1614 не влит, и на
`main` дефект воспроизводится. После слияния прогон повторить теми же командами.

## Что пакет НЕ проверяет

- Ручной smoke под оператором и администратором в браузере: сценарии описаны,
  но прогон на одном зафиксированном SHA возможен только после слияния трёх
  срезов. До тех пор это подготовка тестов, а не заявление «КЦ готов».
- PostgreSQL: прогоны выше сделаны на SQLite. Матрица диалектов закрывается
  обязательным `postgres-integration` на ветках PR.
- Пять конструкций подбора целевой конфигурации, оставшихся за планом 183
  (`ref:` константой, `not_in_hierarchy`, `parent_id` как служебное поле,
  колонка ТЧ в `field`, глубокий источник со скалярным реквизитом): по ним
  нужно решение о контракте, см. комментарий в #1769.

## Структура

```
base/ | full/
  catalogs/    Направление, ГруппаНеисправностей, Неисправность, АдресныйКлассификатор, Филиал
  documents/   Заявка (шапка + ТЧ Строки со ссылкой на подчинённый справочник)
  forms/       управляемая форма заявки
  processors/  ЗаполнитьДемоданные, ПроверитьНеопределено
  roles/       Оператор, Администратор
  src/         код обработок на встроенном языке
```

Справочник «Неисправность» специально содержит одноимённые элементы у разных
направлений («Не включается» и «Прочее» в обоих) — в общем списке их не
различить, и именно это делает отбор по владельцу обязательным, а не
косметическим.
